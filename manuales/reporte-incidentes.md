# Reporte de incidentes

Este manual contiene procedimientos ficticios para probar la búsqueda y las respuestas del RAG.

## Datos del reporte

Para reportar un incidente, describe lo ocurrido, indica la fecha y hora, identifica el servicio afectado y explica cuántas personas no pueden trabajar. Adjunta el mensaje de error y los pasos para reproducir el problema cuando estén disponibles.

No incluyas contraseñas, tokens ni datos personales innecesarios en el reporte. Si adjuntas una captura de pantalla, oculta esa información antes de enviarla.

## Nivel de prioridad

Un incidente es crítico cuando toda la plataforma está inaccesible o hay una pérdida de datos confirmada. El objetivo de primera respuesta para un incidente crítico es de 30 minutos.

Un incidente tiene prioridad alta cuando una función esencial impide trabajar a un área completa. El objetivo de primera respuesta para prioridad alta es de dos horas hábiles.

Un incidente tiene prioridad normal cuando afecta a una sola persona y existe una alternativa para continuar trabajando. El objetivo de primera respuesta para prioridad normal es de un día hábil.

Estos tiempos corresponden a la primera respuesta del equipo responsable; el plazo de resolución depende del diagnóstico.

## Seguimiento y cierre

Conserva el identificador del incidente para consultar su estado. Agrega nueva información al reporte existente en lugar de abrir otro por el mismo problema.

El equipo responsable informa la solución y solicita al usuario que compruebe el funcionamiento. El incidente se cierra cuando el usuario confirma que el problema quedó resuelto.
